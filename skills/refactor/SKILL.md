# Refactor

重构的核心是“行为等价”。不顺带改业务规则，不随意改动公开接口签名。

## 工作顺序

1. **确认不变量**：明确被重构代码的输入输出契约、副作用、异常行为及所有调用方。
2. **建立基线**：重构前先运行现有测试或最小验证脚本，记录基线结果。
3. **小步等价改造**：消除重复、收敛职责或简化分支，保持项目既有命名与目录风格。
4. **回归验证**：重构后再次运行相同的测试或验证命令，确保结果与基线完全一致。
5. **汇报改动**：说明重构了哪些文件、消除了什么坏味道、哪些公共接口保持不变、如何验证等价性。

## 禁止

- 不要在重构中夹带未要求的业务逻辑变更或新特性。
- 未确认所有调用方并获同意前，不要修改对外公开的 API、协议字段或配置项名称。
- 没有把握保持行为一致的部分，停下来说明风险，不要强行重写。
