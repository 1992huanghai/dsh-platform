# Unit Test

先对齐项目现有的测试框架和写法，再编写可运行的测试，不擅自修改被测业务代码。

## 工作顺序

1. **确认被测目标**：读取目标函数/类的签名、输入输出、依赖项和异常分支。
2. **对齐测试约定**：查找仓库已有的测试文件、目录命名、Mock 方式和运行命令。
3. **设计用例**：覆盖正常主路径、边界值（空值、极值、零值）和明确定义的错误路径。
4. **编写并验证**：写入测试文件并执行测试命令。若环境无法运行，说明原因及验证方式。
5. **结果说明**：列出新增的测试文件、覆盖的分支场景，以及执行结果。

## 禁止

- 未经用户同意，不要为了“好测”或“让测试通过”而偷改被测业务代码。
- 不要引入仓库尚未使用的测试框架或断言库。
- 不要写只验证 Mock 本身、不验证真实逻辑的无效断言。
