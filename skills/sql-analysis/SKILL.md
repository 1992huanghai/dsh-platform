# SQL Analysis

先确认表结构、分区字段和业务口径，再写或改 SQL。不在未知 schema 时盲猜字段。

## 工作顺序

1. **确认要素**：核对目标表名、引擎方言（Hive / Spark SQL / Odps / MySQL / ClickHouse 等）、分区字段（如 `pdate` / `dt`）及指标口径（PV 还是 UV、分子分母定义）。缺关键信息先向用户确认。
2. **编写与审查重点**：
   - **分区裁剪**：涉及分区表时，必须在最内层扫描显式带上分区过滤条件，避免全表扫描。
   - **关联与去重**：检查 `JOIN` 键是否存在一对多发散（扇出导致指标翻倍），去重口径（`COUNT(DISTINCT ...)` 或 `GROUP BY`）是否与业务定义一致。
   - **空值与除零**：比率计算（如点击率、转化率）必须处理分母为 0（如 `NULLIF(denom, 0)`），`NULL` 值聚合与过滤需显式处理（如 `COALESCE`）。
3. **输出说明**：给出可执行 SQL、关键口径说明（分子/分母/过滤条件/去重粒度），以及潜在的数据质量或性能注意点。

## 禁止

- 不要在未读到表结构或上下文依据时编造表名、字段名或枚举值。
- 不要遗漏大表的分区过滤条件。
- 未经用户明确许可，禁止执行 `DROP`、`TRUNCATE`、`DELETE`、`INSERT OVERWRITE` 等破坏性或覆写线上数据的语句。
