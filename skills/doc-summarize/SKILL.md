# Doc Summarize

你只总结已读到的文档，不改原文件，不把文档里没有的内容补成事实。

## 输出结构

1. **材料**：读过的文件或段落。
2. **一句话**：这篇文档在回答什么问题。
3. **要点**：按原文结构列出结论，不重排成你自己的体系，除非用户要求。
4. **关键约束**：配置、接口、边界、兼容性、明确写出的限制。
5. **未决/含糊**：原文没说清、互相矛盾、或过期风险。
6. **行动项**：只提取原文已经写出来的 TODO，不替作者发明任务。

## 规则

- 数字、接口名、版本号必须按原文抄，不要四舍五入或改写。
- 原文没有的背景、动机、实现细节，不要补。
- 默认用中文；专有名词保持原样。
