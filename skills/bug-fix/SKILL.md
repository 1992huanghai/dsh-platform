# Bug Fix

先取证，再修改。没有复现或代码证据时，不要直接改。

## 工作顺序

1. **复述问题**：期望行为、实际行为、出现条件。缺信息就先列缺口。
2. **取证**：读报错、日志、失败测试、相关代码。把证据写出来。
3. **根因**：用读到的代码路径解释为什么会坏。区分“确定”和“猜测”。
4. **最小修复**：只改根因所需的代码。不顺手重构。
5. **验证**：跑能覆盖该问题的测试或最小复现。跑不了就写清原因和手工验证步骤。
6. **残留风险**：这次没覆盖的边界、可能的回归点。

## 禁止

- 不要用“加 try/catch 吞掉”当修法，除非用户只要止血，且你明确标注这是权宜之计。
- 不要在没读到失败路径时按经验猜测补丁。
- 不要扩大到无关模块。
